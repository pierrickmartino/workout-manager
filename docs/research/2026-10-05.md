Periodic research sweep for **workout-manager** across six fronts: frontend stack,
backend stack, security advisories against our *actual* dependencies, competitor
gaps, visual-builder UX, and PWA UX. Reviewed main at `21be1c1` (the same SHA the
open audit PR #611 reviewed). **Only this file was written** — no source, config,
lockfile, `GLOSSARY.md` or ADR was touched; every change below is a Next action.

  the `apps/api/pyproject.toml` floors (no lockfile) plus a fresh resolve of those

  installs today.

  claim rests on a search-result summary of those pages and not a page read, the

## Executive summary

- **Act now: Next.js is stuck on a line that no longer gets patches.**
  - We pin `next` **16.2.12**, released 2026-07-25. Every Next.js security fix since
    then shipped only on **16.3.x** (and the 15.5.x backport). No 16.2.13 exists
    ([npm versions](https://www.npmjs.com/package/next?activeTab=versions)).
  - `npm audit` reports three **critical** advisories against our lockfile:
    - [GHSA-2xp9-vwfh-vxw4](https://github.com/advisories/GHSA-2xp9-vwfh-vxw4):
      AVIF image-optimizer RCE, fixed in 16.3.3.
    - [GHSA-p293-qw3h-jr36](https://github.com/advisories/GHSA-p293-qw3h-jr36)
      (CVE-2026-75604): Windows-only RCE, fixed in 16.3.3.
    - [GHSA-vcvr-r3jv-pc5j](https://github.com/advisories/GHSA-vcvr-r3jv-pc5j):
      `next/og` RCE, fixed in 16.3.6.
  - The September 30 release (16.3.8) fixes seven more advisories.
  - **Our code was not found exploitable by any of them.** We run on Linux, use no
    `next/og`, no `images.remotePatterns`, no Pages Router and no `use cache`.
  - But the exact pin plus no update bot means **no** future 16.2-line fix will
    reach us either. Further, the 09-30 post says two more issues (one critical, one
    high) are "pending upstream coordination".
  - **Move to `next@16.3.8`.** 16.3 is reported to have no breaking changes.
    Consider `images.unoptimized: true`, since we never use `next/image`. See
    Security #1.
- **Two Python floors are now badly stale. A fresh resolve is safe, but the floors
  guarantee nothing.**
  - **`pyjwt[crypto]>=2.9`:** 15 advisories at that floor. Ten were published in
    September 2026, one rated critical by GitHub (GHSA-ffc3-869f-jxw9). The latest
    fix is 2.15.0.
  - **`python-multipart>=0.0.12`:** 7 advisories at that floor, including two High
    DoS issues. Our one multipart route is parsed **before** the admin auth
    dependency runs. FastAPI reads the form body before `solve_dependencies`, which
    we checked in the installed source. So parser DoS bugs are reachable without
    authentication.
  - Today's resolve installs PyJWT 2.15.1 and python-multipart 0.0.32, both clean.
  - **Raise both floors**, as was done for Starlette. See Security #2–#3.
- **Major-version drift is now real, and several upgrades are decisions, not
  bumps.**
  - TypeScript **7.0** (the native Go port) went GA on 2026-07-08. We are on 5.9.3.
  - React **19.3.0** shipped on 2026-09-09: View Transitions and Fragment Refs went
    stable, and Trusted Types support was added. We are on 19.2.7.
  - Clerk **@clerk/nextjs 7 (Core 3)** has been out since 2026-03-03. We are on
    6.39.5, and Core 2 support ends about one year after Core 3 shipped (Clerk's LTS
    policy).
  - recharts **3.10.1**. We are on 2.15.4.
  - lucide-react 1.52.0. We are on 1.23.0.
  - Node **22 is in maintenance** and Node 26 becomes LTS this month.
  - Python 3.11 is security-only.
  - On the backend, our unbounded floors already pull **`anthropic` 1.x** and
    **`openai` 3.x** majors. The SDK calls we use still exist in both, which we
    checked.
- **Market: AI hand-off and native health data are the new moves since September;
  the recovery fork is unchanged.**
  - Hevy 3.1.14 (about 2026-09-16) sends a finished workout to ChatGPT or Claude
    from the finish screen.
  - Gript shipped a history- and equipment-aware Workout Generator on 2026-08-28,
    which corrects our own 10-03 claim; the open audit PR #611 already notes this.
  - The watchOS 27 / iOS 27 betas reportedly add per-set strength records (reps,
    weight, equipment, side) to Apple's Workout app. A PWA cannot read or write
    HealthKit.
  - None of this conflicts with an ADR except the wearable/recovery thread (Q1).
- **Builder UX: the ADR-0023/0027 layer now matches the published patterns.** The
  next gaps are triset/circuit (N-member) grouping and undo.
  - Correction to 08-14: the WCAG criterion for "drag must have a single-pointer
    alternative" is **2.5.7 Dragging Movements** (AA, WCAG 2.2), not 2.5.1.
- **PWA: one concrete gap and two platform shifts.**
  - The gap: nothing calls `navigator.storage.persist()`, so the finish outbox in a
    *non-installed* Safari tab is exposed to WebKit's 7-day script-storage eviction.
  - Chrome's `<install>` element / `navigator.install()` origin trial (Chrome
    148–153).
  - Safari 27's Service Worker static routing.
  - Wake Lock in installed iOS PWAs has worked since iOS 18.4.
- **Tracker: one open issue and one open PR** (`gh api`).
  - **#270** (Langfuse, `ready-for-agent`).
  - **PR #611** (the 10-05 product audit, documentation only, "do not merge as part
    of the audit").
  - The 09-25 credential-incident checklist still has four unchecked items.

### F-A · #270 — Langfuse AI-usage monitoring (open, `ready-for-agent`)

- **Status, our side:** the recorder exists. Compose runs a self-hosted
  `langfuse/langfuse:3` server, and the SDK is pinned `langfuse>=2.0,<3`; it resolves
  2.60.10.
- **New this cycle:**
  - The Python SDK is now at **4.16.0** on [PyPI](https://pypi.org/project/langfuse/).
  - Langfuse's compatibility page (seen only as a search summary, because the fetch
    was blocked) says **Python SDK v2 is unsupported after the v4 cutover**, and that
    each server major otherwise supports the current and previous SDK major
    ([compatibility](https://langfuse.com/docs/compatibility),
    [v3→v4 guide](https://langfuse.com/docs/observability/sdk/upgrade-path/python-v3-to-v4)).
  - Our self-hosted **v3** server still accepts a v2 SDK under that rule, so #270 is
    not blocked. But upgrading the self-hosted server to v4 would drop our recorder.
- **Related:** FastAPI **0.142.0** added *native OpenTelemetry* support, and 0.142.2
  fixed "allow startup when automatic OpenTelemetry configuration fails"
  ([FastAPI releases](https://github.com/fastapi/fastapi/releases)).
  - The v4 Langfuse SDK is OpenTelemetry-native. The 08-14 cost warning (unrelated
    spans inflating traces) therefore now applies twice. If FastAPI's OTel is
    switched on, scope Langfuse span capture to LLM calls only.
- **Bears on #270's acceptance:**
  - Add "pin the Langfuse server image to v3.x (not `:3` floating past a v4 cutover)
    until the recorder is rewritten".
  - Record the SDK-v2 end-of-support risk in ADR-0039's follow-up, not in the ADR
    body.

### F-C · Dependency-cadence decision (08-14 Q2, still open; now evidenced)

The exact-pin convention (CLAUDE.md) did what it promised: the lockfile did not move
silently. But with no update bot, **an exact pin is also how a critical advisory
sits unpatched for 41 days.** The first fix (16.3.3) shipped on 2026-08-25, and this
sweep found it on 2026-10-05.

The convention says "let CI judge it". That only works if something proposes the
bump. A Renovate or Dependabot config that opens exact-version PRs keeps the
convention and closes this gap. This is the strongest argument yet for 08-14 Q2.

Nothing in this sweep changes that. It remains the highest-severity *non-dependency*
security item, and it is an owner task.

### Visual workout-builder UX (for the shipped ADR-0023/0027/0068 layer)

- **Grouping by drop-onto.** Coach builders make a superset by dragging one exercise
  onto another; a third member makes a triset and a fourth a circuit, shown with a
  coloured group border
  ([TrainHeroic](https://support.trainheroic.com/hc/en-us/articles/18156598268429-For-Coaches-Creating-Supersets),
  [Gymkee](https://gymkee.com/help/coach/create-supersets-trisets-circuits-amrap-emom-tabata-etc/)).
  - Our overlay already allows N contiguous members (`lib/supersets.ts`).
  - The gap is *affordance*: "drop onto a row to group" as a drag target, with
    `Link2`/`Unlink` as the button floor.
- **A checkbox-select-then-group mode** is the documented non-drag alternative for
  grouping. It also satisfies **WCAG 2.5.7 Dragging Movements** (only the end result
  needs a single-pointer path)
  ([W3C Understanding 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html),
  [SCR27 reorder technique](https://www.w3.org/WAI/WCAG21/Techniques/client-side-script/SCR27)).
- **Section templates.** Coach tools ship reusable section templates; HubFit's
  Training v2 ships a builder with section templates and custom fields
  ([HubFit changelog](https://hubfit.com/changelog/training-v2)).
  - For us that is "save this Session as a template", which is the 09-01 P1 still
    open.
  - ADR-0043's duplicate-with-lineage is the mechanism: a template is a duplicate
    source, not a new entity.
- **Undo over confirmation for reorder and remove.** The 09-01 report recommended
  it. ADR-0098 governs *irreversible* confirmations. Reorder and remove inside the
  un-performed tail are reversible and should get Undo, not a dialog. No 2026
  primary source was found specifically on undo toasts, so this is a design judgement.
- **Progressive disclosure is already the pattern:** "More — round rest" in
  `prescription-rows.tsx`. Keep set type, effort and tempo behind it (ADR-0065
  keeps them optional).

### PWA UX (ADR-0028 / 0036 / 0055 / 0059–0061 in force)

- **P-1 · Ask for persistent storage when the outbox is non-empty.**
  - Nothing in `apps/web` calls `navigator.storage.persist()`.
  - WebKit exempts *Home Screen web apps* from the 7-day script-storage cap, but a
    plain Safari tab is not exempt.
  - Safari and Chromium grant `persist()` from heuristics, with no prompt
    ([WebKit storage policy](https://webkit.org/?p=14403),
    [MDN quotas](https://developer.mozilla.org/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)).
  - A pending finish in the IndexedDB outbox (ADR-0060) is exactly the data that
    must survive eviction.
- **P-2 · The install prompt is becoming declarative.**
  - Chromium has an `<install>` element and `navigator.install()` in origin trial
    (Chrome 148–153)
    ([Chrome blog](https://developer.chrome.com/blog/install-element-ot),
    [InfoQ](https://www.infoq.com/news/2026/03/web-install-api-origin-trial)).
  - We have no `beforeinstallprompt` handling. The 09-01 advice to offer install
    after a meaningful action (a finish) maps cleanly onto `<install>` once it
    ships, so wait for it rather than building a custom prompt now.
- **P-3 · Update flow.**
  - `public/sw.js` calls `skipWaiting()` and `clients.claim()` immediately.
  - Because it is network-only for navigations and precaches only `/offline`, an
    instant takeover cannot strand a Live Session's data. The Live slot and outbox
    are separate stores (ADR-0035/0059).
  - The residual risk is a stale client chunk after a deploy, not the SW.
  - Chrome's new two-week stable cadence (from Chrome 153) means more frequent
    browser-side changes; re-run the device matrix per release
    ([Chrome blog](https://developer.chrome.com/blog/chrome-two-week-start)).
- **P-4 · Safari 27 adds Service Worker static routing**
  ([WebKit](https://webkit.org/blog/18325/webkit-features-for-safari-27-0/),
  [explainer](https://github.com/WICG/service-worker-static-routing-api)).
  - It could let `/_next/static/*` bypass SW startup entirely.
  - The benefit is unmeasured for a fetch handler that already ignores
    non-navigations. Low priority.
- **P-5 · Wake Lock works in installed iOS PWAs since iOS 18.4**
  ([WebKit bug 254545](https://bugs.webkit.org/show_bug.cgi?id=254545)).
  - `lib/wake-lock.ts` and ADR-0055 are viable on iPhone Home Screen apps.
  - Add an installed-iOS row to the device matrix.
- **P-6 · Push stays out of scope.**
  - Declarative Web Push (Safari 18.4+/iOS 18.4+) removes the SW requirement for
    notifications ([WWDC25 session](https://developer-mdn.apple.com/videos/play/wwdc2025/235)).
  - Any reminder-style push that implies "today" conflicts with ADR-0001's
    calendar-free model. Background Sync remains absent on iOS, so the outbox's
    retry on regained connectivity (`lib/use-connectivity.ts`) remains the right
    design.
- **P-7 · Manifest.**
  - `public/manifest.json` has no `id`, `screenshots`, `shortcuts` or `scope`.
  - A stable `id` and a "Resume Live Session"/"Log a workout" shortcut are cheap.
    Screenshots enable Chrome's richer install UI
    ([web.dev manifest](https://web.dev/learn/pwa/web-app-manifest)).
  - Keep `theme_color` consistent with ADR-0102's per-Skin `generateViewport()`.
    The static value is only the install-time fallback.

## Questions

1. **Wearable/recovery posture (carried Q1; pressure up).**
   - SensAI (August), MacroFactor's in-session fatigue estimate and Apple's richer
     strength records all push toward a recovery or readiness *score*.
   - ADR-0001 and ADR-0008 forbid a recovery % and "today", and Readiness stays
     3-state (GLOSSARY 'Readiness').
   - Hold the line, or open a bounded lane that only feeds the 3-state signal? This
     needs an ADR before any issue.
2. **Native shell or PWA-only?**
   - If watchOS 27 / iOS 27 really expose set-level strength data in HealthKit
     (unverified), sync with Apple Health becomes a real gap a PWA cannot close
     (ADR-0028).
   - Revisit the 10-03 Gript audit §7 (native client) once the iOS 27 developer docs
     can be read first-hand.
3. **"Send to an AI" hand-off (Hevy parity)?**
   - A copy-to-clipboard or export of one Logged Session as an LLM-ready summary is
     a read-time projection (ADR-0018 style) and needs no new storage.
   - Do we want to make it easy to move health data into a third-party assistant,
     and should Sensitive-Constraint users see a caveat, as ADR-0058 does for
     shares?
4. **Clerk Core 3: when?**
   - Core 2 is in LTS (critical patches only) until about March 2027 (inferred from
     Clerk's one-year policy).
   - The upgrade touches `SignedIn`/`SignedOut` in the root layout. It also changes
     offline `getToken()` semantics, which interacts with the outbox and the
     Calibration catch paths (PR #611 rank 2).
   - Schedule it before Q1 2027, or bundle it with the TS and React majors?
5. **Dependency automation (08-14 Q2, re-asked with evidence).**
   - Adopt Renovate or Dependabot with exact-version PRs, plus a weekly
     `npm audit` / `pip-audit` CI job?
   - And should `apps/api` gain a lockfile (`uv lock`)? The `>=` floors are
     documented as security minimums, but three of them (Starlette, PyJWT,
     python-multipart) have now gone stale between sweeps.
6. **Redis 7 → 8 and Postgres 16 → 18/19?**
   - Both images float on a major tag. A Redis major is cheap for an RQ-plus-cache
     workload.
   - A Postgres major needs the dump-and-restore path the VPS guide warns about.
     Do we keep 16 until 19 is GA?
