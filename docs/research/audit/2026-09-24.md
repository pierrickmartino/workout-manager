## Five improvements, ranked

| Rank | Improvement | User impact / risk | Effort | Confidence |
|---|---|---|---|---|
| 1 | Revoke exposed tokens and prevent another commit | Critical account and data risk | S to revoke; M if history cleanup is needed | High exposure; token validity unverified |
| 2 | Commit a finish and all its sets atomically | High risk of an incomplete record reported as synced | M | High from source; failure not reproduced |
| 3 | Reject stale exercise-catalog responses | Medium risk of showing results for the wrong filters | S | High from source; timing dependent |
| 4 | Recover substantial unsaved workout drafts | High potential work loss during creation or correction | M | Medium; user frequency unknown |
| 5 | Repair shared form labels and error feedback | Medium onboarding and accessibility risk | M | High for markup; device impact unverified |

1. **Credential exposure — status: shipped exposure, current validity unverified.** The problem is that repository readers can retrieve populated token fields from a tracked file introduced in a [11 September commit](https://github.com/pierrickmartino/workout-manager/commit/a19fde3bfa2eb61485481ac7ee831991af85b8c6). Revoke the credentials, inspect the rest of the committed tool-state directory for secrets without publishing values, remove it from tracking, add ignore and secret-scanning protection, then decide whether coordinated history cleanup is warranted. **Benefit:** removes a potentially usable credential and prevents recurrence. **Success:** all exposed credentials are revoked, the file is absent from current branches, and a test push containing a representative secret is blocked. **New issue draft:** “Revoke exposed Codex tokens and remove tracked tool state”; acceptance criteria are those three checks.

2. **Atomic finish — status: partially shipped.** The [SQL repository commits the session row](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/api/app/repositories/logged_session_repository.py#L267-L305) *before* adding and committing its sets. On retry, its key lookup returns the existing row immediately. Thus a failure between commits can leave a record with no sets that a retry treats as success. The [retry tests](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/api/tests/test_logged_session_repository.py#L241-L259) cover completed writes, not that interruption. Insert row and sets in one transaction, flush to obtain the row ID, commit once, and make a concurrent same-key retry resolve to the completed owner-scoped record. **Benefit:** a “Synced” finish corresponds to all performed sets. **Success:** injected failure before commit leaves zero rows; concurrent and post-commit retries yield exactly one complete Logged Session. Related closed [#407](https://github.com/pierrickmartino/workout-manager/issues/407) covers the broader outbox; this transaction defect is distinct. **New issue draft:** “Make idempotent Logged Session creation atomic”; acceptance criteria are the failure and retry checks above.

3. **Catalog result ordering — status: partially shipped.** Filters and URLs now update, but an earlier in-flight request can still call setTaxonomy after a later one; the effect’s cleanup only cancels the [debounce timer](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/components/ExerciseCatalogTaxonomy.tsx#L94-L114). Ignore responses whose request sequence or filter key is no longer current, including stale errors. **Benefit:** exercise choices match the visible search and facets. **Success:** a test resolving request A after request B still displays B’s results and error state. **New issue draft:** “Ignore superseded catalog filter responses”; acceptance criterion is that reversed-response test.

4. **Draft recovery — status: partially shipped.** The hand-authored form has a [dirty-navigation guard](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/components/HandAuthoredSessionForm.tsx#L249-L259), as do ad-hoc logging and correction, but their entered rows are not durable across a closed tab or browser restart. Save a versioned, account-scoped draft for these forms; offer restore or discard, clear it only after an acknowledged save, and keep draft data separate from the Live Session and finish outbox. **Benefit:** an interrupted builder or correction does not require re-entry. **Success:** reload, tab closure, and account-switch tests restore only the owner’s unsaved fields, with no duplicate submitted record. **Hypothesis:** interruptions are common enough to justify persistence; measure this before expanding beyond these forms. **New issue draft:** “Recover account-scoped workout form drafts”; acceptance criteria are the restore, isolation, and clear-on-success checks.

5. **Form accessibility — status: partially shipped.** Shared [Field renders nested label elements](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/components/pulse/field.tsx#L15-L33); its hint has no control association. [Profile errors](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/components/ProfileForm.tsx#L39-L75) appear above the form without field targeting, while the shared [Alert](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/components/pulse/alert.tsx) supplies no announcement role by default. Give each control one explicit label and associated hint; announce dynamic errors, identify invalid fields, and move focus to the first error or summary. **Benefit:** clearer onboarding and correction for keyboard and screen-reader users. **Success:** automated markup checks pass and a manual screen-reader pass announces labels, hints, and a failed profile submission in order. **New issue draft:** “Fix shared field associations and profile error focus”; acceptance criteria are those checks.

## This week and what to validate

**Small deliverable:** Fix catalog response ordering (rank 3). It has a narrow code path, a deterministic reversed-response test, and no domain or ADR change.

**One question before a larger offline build:** When connectivity disappears, do users chiefly need to **continue a Live Session already open**, or **reopen a planned Session after the app has closed**? The current service worker deliberately serves an [offline fallback for navigations](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/public/sw.js#L45-L59) and does not cache authenticated pages under [ADR-0028](../../adr/0028-web-pwa-is-installable-and-offline-aware-but-caches-no-authenticated-navigation.md). Reopening private plan data offline would require a new account-scoped data design and an explicit change to that decision. Test both journeys with users before building it.
