**Original security finding:** The reviewed main commit contained [.codex/auth.json](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/.codex/auth.json) with populated access, refresh, and ID token fields. Their values are not reproduced here, and whether they remain valid was not checked. **Revoke the exposed credentials first**, then remove the tracked file and prevent recommits. Removing it in a new commit alone leaves historical copies. [GitHub's guidance](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) puts revocation before any decision to rewrite history.

**Remediation update — 26 September 2026:** Repository containment shipped on `main` in [7fbc977](https://github.com/pierrickmartino/workout-manager/commit/7fbc977). The complete 220-file `.codex` tool-state tree was removed from tracking while preserving local runtime state, and the root path is now ignored. A redacted Gitleaks inspection covered the committed tree; its value-free findings and the response record are documented in the [incident report](../../security/incidents/2026-09-25-codex-tool-state.md). A fail-closed local pre-push hook and blocking CI workflow now reject tracked `.codex` state and scan every introduced commit, including merge second parents. Automated tests confirmed that a representative populated token is rejected without updating the test remote and that add-then-delete and merge-history cases are detected.

The current `main` tree no longer contains the exposed file. Closure is not complete: provider-side revocation of the opaque refresh credential remains unverified, retained remote branch tips have not all been remediated, and GitHub native secret scanning and push protection still need to be enabled and tested with GitHub's official dummy secret. A coordinated history rewrite is therefore deferred, not ruled out: after revocation is verified, its disruption and recontamination risk outweigh its benefit for this credential; revisit it if revocation cannot be verified or the remaining artifacts contain non-revocable confidential material.

**Catalog-ordering remediation update — 26 September 2026:** The Catalog client now assigns each debounced filter read a sequence-and-filter-key ticket and invalidates the current ticket synchronously when visible filters change. Effect cleanup cancels both the debounce timer and its ticket, and only the current ticket may commit taxonomy results or errors. A focused reversed-response test resolves request B before request A and confirms that A cannot replace B's displayed results or error. The focused TypeScript check and complete frontend suite pass under Node 22.

**Atomic-finish remediation update — 26 September 2026:** The SQL Logged Session repository now flushes the session row only to obtain its id, adds every Logged Set in the same transaction, and commits once. Any failure rolls the transaction back; when concurrent requests race on one idempotency key, the uniqueness loser rolls back and resolves only the completed record matching both the owner and key. A fault-injection test fails while attaching the first set and confirms that zero Logged Sessions remain, a deterministic two-session race confirms that both requests resolve to one complete owner-scoped record, and the post-commit retry test confirms that the returned record retains its sets. All 46 Logged Session repository tests, 27 related logbook/record tests, and the authored endpoint retry tests pass; the full API run now collects but has seven unrelated model-configuration failures because the environment forces one default Google model for every provider. A focused security review found no authorization, cross-owner disclosure, or transaction-race issue.

**Draft-recovery remediation update — 26 September 2026:** The Hand-Authored Session (including Build and Capture), plan-less ad-hoc log, and Log Correction journeys now persist versioned drafts in a dedicated account-and-form scoped `localStorage` collection. Reload, tab closure, and browser restart offer only the current owner’s fields; Restore and Discard are explicit, malformed/oversized/unsupported data fails closed, and account changes remount the form. Drafts remain separate from Live Session state and the finish outbox; sign-out purges them and disables a final pagehide flush. A draft clears only after an acknowledged server save. Author-and-log and ad-hoc drafts retain client UUID idempotency keys; sequential and concurrent authored retries resolve to one plan/Logged Session pair. ADR-0080 records the boundary and the decision to measure restore frequency before expanding recovery. The focused web storage/validation tests (10), full frontend suite (1,256), and focused authored endpoint/repository suites (69) pass. The full API run has seven unrelated model-configuration failures because the environment forces one default Google model for every provider.

1. **Credential exposure — status: repository containment shipped; credential revocation and cross-branch closure unverified.** Repository readers could retrieve populated token fields from a tracked file introduced in a [11 September commit](https://github.com/pierrickmartino/workout-manager/commit/a19fde3bfa2eb61485481ac7ee831991af85b8c6). Commit [7fbc977](https://github.com/pierrickmartino/workout-manager/commit/7fbc977) removed the complete tool-state directory from the current `main` tree, added ignore and secret-scanning protection, and supplied regression tests. A value-free inspection found expired JWTs, false positives, and one opaque refresh credential whose provider-side revocation cannot be inferred from repository state. The representative local test push is blocked, but the original success criteria are only partially met: revocation is unverified, and the file must still be removed from every retained branch. GitHub-native push protection also remains to be enabled and tested. The history-cleanup decision and remaining evidence are recorded in the [incident report](../../security/incidents/2026-09-25-codex-tool-state.md). **Benefit:** removes a potentially usable credential and prevents recurrence. **Success:** all exposed credentials are revoked, the file is absent from current branches, and a test push containing a representative secret is blocked. **New issue draft:** “Revoke exposed Codex tokens and remove tracked tool state”; acceptance criteria remain those three checks.

2. **Atomic finish — status: implemented in source; full API suite pending.** At the reviewed commit, the [SQL repository committed the session row](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/api/app/repositories/logged_session_repository.py#L267-L305) *before* adding and committing its sets, so an interruption could leave an empty record that a retry treated as success. The [repository now](../../../apps/api/app/repositories/logged_session_repository.py) flushes the row to obtain its id, attaches every set, and commits once; every failure rolls back. A concurrent uniqueness loser also rolls back before looking up the winner by both owner and idempotency key, so it cannot return another account's record. The [regression tests](../../../apps/api/tests/test_logged_session_repository.py) inject a failure while attaching the first set, deterministically insert a competing same-key finish between lookup and flush, and verify a normal post-commit retry. **Benefit:** a “Synced” finish corresponds to all performed sets. **Success:** met by the focused tests: the injected failure leaves zero rows, while concurrent and post-commit retries yield exactly one complete Logged Session. All 46 repository tests and 27 related logbook/record tests pass; repository-wide API verification remains pending because the local environment cannot collect endpoint tests without its declared `python-multipart` dependency. Related closed [#407](https://github.com/pierrickmartino/workout-manager/issues/407) covers the broader outbox; this transaction defect was distinct. No domain or ADR change was required.

3. **Catalog result ordering — status: implemented in source; frontend verification passes.** The [Catalog component](../../../apps/web/components/ExerciseCatalogTaxonomy.tsx) now invalidates the active request as soon as filters change, creates a sequence-and-filter-key ticket before each debounce starts, and cancels that ticket during effect cleanup. The [request coordinator](../../../apps/web/lib/latest-catalog-request.ts) commits neither results nor errors once its ticket is superseded. The [regression test](../../../apps/web/lib/latest-catalog-request.test.ts) resolves request B before request A and confirms that B's results and error remain displayed after stale A completes. **Benefit:** exercise choices match the visible search and facets. **Success:** met by the focused reversed-response test; the focused TypeScript check and complete frontend suite pass under Node 22.

4. **Draft recovery — status: implemented in source; restore frequency remains to be measured.** The [dedicated draft store](../../../apps/web/lib/form-draft-storage.ts) holds versioned, account-and-form scoped entries for Hand-Authored Session authoring (including Build and Capture), ad-hoc logging, and Log Correction. Each form offers [Restore draft or Discard draft](../../../apps/web/components/FormDraftRecovery.tsx); account changes remount the form, bounded validators fail closed on malformed or oversized local data, and sign-out clears the store. Drafts clear only after an acknowledged server result; failures leave them available. Author-and-log and ad-hoc submissions retain client UUID idempotency keys; the authored API resolves concurrent retries to one plan/record pair, while correction uses its existing full-replacement record identity. The [storage and validation tests](../../../apps/web/lib/form-draft-storage.test.ts) pass, the complete frontend suite passes, and the [authored endpoint regression](../../../apps/api/tests/test_authored_session_endpoint.py) covers sequential and concurrent retries. **Benefit:** an interrupted builder or correction no longer requires re-entry. **Success:** owner isolation, restore/discard, tab/reload durability, sign-out teardown, clear-on-success, and duplicate-record protections are implemented in source/tests. **Hypothesis:** interruptions are common enough to justify persistence; measure restore/discard frequency before expanding beyond these forms. **New issue draft:** “Recover account-scoped workout form drafts”; acceptance criteria are met by the restore, isolation, and clear-on-success checks.

5. **Form accessibility — status: partially shipped.** Shared [Field renders nested label elements](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/components/pulse/field.tsx#L15-L33); its hint has no control association. [Profile errors](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/components/ProfileForm.tsx#L39-L75) appear above the form without field targeting, while the shared [Alert](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/components/pulse/alert.tsx) supplies no announcement role by default. Give each control one explicit label and associated hint; announce dynamic errors, identify invalid fields, and move focus to the first error or summary. **Benefit:** clearer onboarding and correction for keyboard and screen-reader users. **Success:** automated markup checks pass and a manual screen-reader pass announces labels, hints, and a failed profile submission in order. **New issue draft:** “Fix shared field associations and profile error focus”; acceptance criteria are those checks.

**Form-accessibility remediation update — 26 September 2026:** Shared Field and compact FieldLabel now render one explicit label targeting a stable control ID. Hints and inline errors are associated through `aria-describedby`, preserving existing descriptions and excluding auxiliary buttons. Alert defaults to `alert` for errors and `status` for informational messages and confirmations; callers can override the role. Profile submissions validate numeric values before saving, mark offending controls `aria-invalid`, announce the error summary, and focus the first invalid control or the summary for general API/network failures. Failed submissions retain attempted values, including on repeated failures. Automated rendered-markup, React DOM submission/focus, and numeric-validation checks pass, alongside the complete frontend suite and TypeScript check. A manual screen-reader pass remains **pending**, so item 5 is implemented in source but its full acceptance criteria are not yet verified. The [handoff and manual check procedure](../../development/form-accessibility-handoff.md) record the remaining check.

**One question before a larger offline build:** When connectivity disappears, do users chiefly need to **continue a Live Session already open**, or **reopen a planned Session after the app has closed**? The current service worker deliberately serves an [offline fallback for navigations](https://github.com/pierrickmartino/workout-manager/blob/4aefcf7d6183936cd0544c28a53414be832806ea/apps/web/public/sw.js#L45-L59) and does not cache authenticated pages under [ADR-0028](../../adr/0028-web-pwa-is-installable-and-offline-aware-but-caches-no-authenticated-navigation.md). Reopening private plan data offline would require a new account-scoped data design and an explicit change to that decision. Test both journeys with users before building it.
